# INTP 키우기 — 방 (Vertical Slice, Python/Web)

2026-10-07 확정 요구사항명세서(`intp키우기_요구사항명세서_261007.docx`) 기준으로 **처음부터 다시 만든** 버전입니다.
이전의 스탯 육성/코덱스/이벤트 팝업 구조는 전부 버리고, 명세서가 요구하는 **"방 한 칸 + 관찰 → 질문 → 탐구 → 가설 → 검증"** 루프로 새로 설계·구현했습니다.

사용자가 선택한 순서대로, **이번 라운드는 Python 웹 버전만** 완성합니다. **Kotlin/Android 포팅은 이 버전을 플레이해보고 검증한 뒤, 다음 라운드에서 별도로 진행**합니다 (요구사항명세서의 "작업 환경은 python, kotlin"은 유지하되, 질문에 답변주신 "Python 웹 버전 먼저 완성 → 검증 후 Kotlin 포팅" 순서를 따랐습니다).

## 1. 실행 방법

이 프로젝트는 **FastAPI**로 작성되어 있습니다 (`app/main.py`).

```bash
pip install fastapi uvicorn jinja2
cd intp_room
uvicorn app.main:app --reload --port 8000
# http://localhost:8000 접속
```

> **직접 `room_editor/index.html`을 더블클릭(`file://`)해서 열면 안 됩니다.** 이 화면은 서버의
> `/api/*`를 호출해서 시간/관찰/가설 같은 실제 게임 로직을 가져오는데, `file://`로 열면
> 같은 출처(same-origin)가 아니라서 그 호출이 전부 실패합니다. 반드시 위처럼 서버를 띄운 뒤
> 브라우저 주소창에 `http://localhost:8000`을 입력해서 접속해야 합니다.

### 1-1. 화면(프런트엔드) 구조 — 가구 배치 편집기 기반으로 교체됨

`/`(루트)가 보여주는 화면은 더 이상 `app/templates/index.html`(옛 아이소메트릭 그리드 버전)이
아니라, `room_editor/`에 있는 "가구 배치 편집기" 프로젝트가 만든 `room_editor/index.html`입니다.
(옛 화면 파일들 — `app/templates/index.html`, `app/static/room.js`, `app/static/room.css` —
은 라우트에서 빠졌을 뿐 그대로 남아 있습니다.)

- **방/캐릭터**: 직접 배치하신 가구 위치(`room_editor/my-layout-261008.json`)를 그대로 쓰고,
  바닥을 탭/클릭하면 캐릭터가 걸어서 이동하며 가구에는 부딪혀 막힙니다.
- **가구 접근**: 가구나 문을 누르면 — 멀리 있으면 먼저 그 자리까지 걸어간 뒤에, 가까이 있으면
  바로 — 상호작용 창이 열립니다. "관찰하기" 버튼 하나로 다 처리하던 방식에서, 가까이 가야만
  상호작용할 수 있는 방식으로 바뀌었습니다.
- **콘텐츠**: 그 상호작용 창에서 보여주는 내용(관찰→질문→탐구→가설→검증)은 전부 기존
  `app/engine/*`를 그대로 호출해서 가져옵니다 — 이번에 콘텐츠를 새로 쓰지 않았습니다.
- **가구 ↔ 기존 11개 오브젝트 매핑**: `bed→bed, radio→radio, mirror→mirror, boxes→boxes,
  window→window, shelf→bookshelf, board→memowall, drawer→mail`은 이름만 다르고 1:1로
  대응됩니다. `desk`는 그림에 모니터가 같이 그려져 있어서 책상(desk)+컴퓨터(computer)를
  한 가구로 합쳐서 보여줍니다("책상 위 정리"와 "컴퓨터로 검색"이 같은 창에 나옵니다). `door`(문)는
  가구 배치 JSON에는 없고 배경 그림에 이미 그려져 있어서, 그 위치에 보이지 않는 히트박스를
  하나 따로 추가했습니다(편집기에는 안 잡힙니다).
- **없어진 것**: 옛 화면의 "다음 시간 →" 버튼은 숨겼습니다 — 이제 시간은 (옛 버전과 똑같이)
  실제 행동(관찰/검색/읽기 등)을 할 때만 흐릅니다.
- **바뀐 것**: "기록" 버튼이 서버의 실제 로그(`/api/state`의 `log`)를 보여주도록 다시 연결됐고,
  상단 시계도 매 로드/상호작용 때마다 서버 상태로 갱신됩니다.

편집기 자체(가구 위치를 다시 조정하고 싶을 때)는 그대로 `room_editor/` 안에서
`python3 build.py`로 빌드합니다 — `room_editor/source-261008.html`과 `room_editor/src/*`는
직접 건드리고, `room_editor/index.html`은 빌드 결과물이라 손으로 고치면 안 됩니다. 수정 후엔
`room_editor/index.html`을 다시 빌드하면 서버가 바로 그 파일을 읽어서 보여줍니다(재시작만
하면 됩니다. 서버가 파일을 캐싱하진 않지만 `--reload` 없이 띄웠다면 프로세스를 재시작해야
새 `index.html`이 반영됩니다).

저장 파일은 `app/data/saves/<세션id>.json` 에 생성됩니다. 브라우저 쿠키(`intp_room_session`)로 세션을 구분하며, 서버를 껐다 켜도(프로세스가 완전히 새로 떠도) 같은 쿠키로 접속하면 저장된 상태를 그대로 불러옵니다 — 별도의 "불러오기" 버튼 없이 자동 재개되는 방식입니다.

> `shim.py`는 실제 배포본이 **아닙니다.** 이 샌드박스에 PyPI 접근 제한이 있어 fastapi/pytest를 설치할 수 없었기 때문에, 이미 깔려 있던 starlette/uvicorn/jinja2로 `app/main.py`와 라우트 단위로 100% 동일하게 만든 로컬 검증용 미러입니다. 실제로 쓰실 땐 `app/main.py` (FastAPI)만 보시면 됩니다.

24/24, 27/27, 17/17, 21/21 통과. 핵심 분리 원칙(세계의 사실 / 관찰한 사실 / 추론)을 비롯해 아래 "기술 완료 기준" 각 항목을 직접 테스트로 검증합니다. 자동 테스트와 별개로, 이 세션에서 Playwright로 실제 브라우저에서 "상자 정리 → 밤 되길 기다림 → 창문으로 밤바다 불빛 관찰 → 컴퓨터 검색 → 책장 읽기 → 책상에서 가설 작성/수정 → 메모벽 확인 → 저장 → 서버 프로세스 재시작 후 같은 쿠키로 복귀" 전체 흐름과, 쌍안경 확대 관찰, 문의 엔딩 전환까지 전부 눈으로 직접 확인했습니다.

## 3. 그래픽에 대해 (중요)

처음엔 레퍼런스 이미지 같은 실제 픽셀아트를 만들 방법이 없어서(이 세션엔 이미지 생성 도구가 없고, 연결 가능한 MCP 커넥터 중에도 없었습니다) 단순 사각형 그래픽으로 시작했습니다. 이후 **itch.io의 무료 에셋팩 "Isometric pixel bedroom" (by Sweeetpotatoo, "Free to use anywhere", AI 생성 아님)**을 찾아서 실제 픽셀아트로 교체했습니다 — 레퍼런스 이미지와 이름·스타일이 거의 동일해서, 레퍼런스의 원출처이거나 매우 가까운 소스로 보입니다.

- https://sweeetpotatoo.itch.io/isometric-pixel-bedroom

렌더링을 **아이소메트릭(isometric) 투영**으로 완전히 새로 짜고, 침대/책장/책상/거울/이삿짐 상자/러그는 이 팩의 실제 스프라이트를 씁니다 (`app/static/sprites/`). 다만 이 팩은 범용 침실 팩이라 컴퓨터 모니터·라디오·메모벽(코르크보드)·우편함처럼 이 게임에만 있는 오브젝트는 실제 스프라이트가 없어서, 그 네 개만 간단한 도형 아이콘으로 그렸습니다(`room.js`의 `drawIconProp`). 이동/충돌/상호작용 로직은 격자(그리드) 좌표 그대로이고 그 위에 화면 투영만 아이소메트릭으로 바뀐 것이라, 게임 로직은 전혀 안 건드렸습니다 — 렌더링 코드는 `room.js`의 `drawFloorAndWalls` / `drawObjects` 에 모여 있어서 나중에 다른 팩이나 커스텀 스프라이트로 또 바꾸기도 쉽습니다.

| 7 | 책상에서 관찰과 추론을 분리하고 가설을 생성/수정한다 | ✅ | 책상 모달이 관찰/정보/가설을 분리된 섹션으로 표시 |
| 8 | 반례의 근거와 틀린 가설 및 수정 이력이 남는다 | ✅ | 가설은 삭제되지 않고 `revisions`에 원문+사유가 누적. `test_wrong_hypothesis_is_revised_not_deleted` + 실브라우저 확인 |
| 9 | 살아남은 질문이 메모벽에 나타난다 | ✅ | 관찰 2회+수정 1회 이상이면 자동 게시 (플레이어가 직접 핀 꽂지 않음). `test_memo_wall_and_exit_unlock_after_enough_investigation` |

**14/14 충족.**

### 이번 라운드에 추가로 고친 것 (체크리스트 검증 중 발견)

- **문/우편물 근접 판정 충돌**: 지도상 문으로 접근 가능한 칸이 단 한 칸뿐인데, 그 칸이 우편물 오브젝트와도 인접해 있어서 둘 중 먼저 등록된 우편물이 항상 이겨버리는 바람에 **문을 영영 선택할 수 없는 버그**였습니다. 우편물 위치를 옮겨서 해결했고, 같은 종류의 문제가 다른 오브젝트에도 없는지 자동으로 검사하는 테스트(`test_every_essential_object_has_an_unambiguous_approach_tile`)를 추가했습니다.
- **상호작용 패널이 매 프레임 다시 그려지던 문제**: 근처 오브젝트가 안 바뀌었는데도 60fps로 버튼을 매번 새로 만들어서, 클릭 도중 버튼이 DOM에서 사라지는 경우가 있었습니다 (자동화 테스트에서 발견했지만 실제 사용자 클릭에도 영향 줄 수 있는 문제). 오브젝트가 바뀔 때만 다시 그리도록 고쳤습니다.

### 이번 라운드(가구 배치 편집기 프런트엔드 연동) 중 발견하고 고친 것

- **문 히트박스가 서랍장(우편물)과 겹치는 문제**: 옛 그리드 버전에서 났던 것과 같은 종류의
  버그가 새 화면에서도 똑같이 재현됐습니다. 문은 가구 배치 JSON에 없어서 배경 그림 좌표
  (965, 520) 근처에 보이지 않는 히트박스를 추가했는데, 그 자리가 바로 옆 `drawer`(편지
  서랍장, bounds 870~1002, 463~593)와 겹쳐서 문을 눌러도 서랍장이 열렸습니다. 문 쪽
  히트박스를 서랍장 영역과 안 겹치게 오른쪽으로 옮기고(`room_editor/src/game-interact.js`의
  `DOOR_POS`/`DOOR_HOTSPOT_CENTER`), 혹시 모를 또 다른 겹침에 대비해 문 히트박스의
  `z-index`를 가구보다 높여 항상 우선 클릭되게 했습니다. Playwright로 문을 눌렀을 때 실제로
  "문" 모달이 뜨는지(서랍장이 아니라) 재확인했습니다.

### 알려진 경미한 한계

- 컴퓨터/라디오/메모벽/우편물은 (3번 항목에서 설명했듯) 에셋팩에 맞는 스프라이트가 없어서 단순 아이콘입니다. 라벨 위치도 오브젝트가 몰려있는 구간(책장↔이삿짐 상자 등)에서 살짝 겹칠 수 있는데, 기능엔 지장 없습니다.

## 6-2. 자동 연결 시스템 (자동연결시스템_개발명세서_261012)

창문 관찰 문장이 정해지고 기록된 직후, 그 문장을 트리거로 하는 연결 정의(`app/engine/connection.py`의

붙여 **하나의 일지 항목**으로 출력합니다. 추가 턴은 없고, 일반 관찰의 선택 확률도 바꾸지 않습니다.

| 사례 | 트리거 | 선행 조건 (실제 기록에서만 확인) | 상태 |
|---|---|---|---|
| C01 바람과 파도 | SEA-007 ↔ SEA-009 (순서 무관) | 반대 장면 관찰 | 구현. 2단계: 1단계 뒤 SEA-008 |
| C02 개미와 강아지 | DOG-004 / DOG-014 / DOG-018 | 지식 `ant_pheromone` 접함 (YARD-002) | 구현 (실제 콘텐츠 존재) |
| C03 소녀와 강아지 | DOG-023 | SHOP-012 / SHOP-027 / SHOP-032 / DOG-026 중 하나 | 구현 |
| C04 밤바다 불빛과 부표 | 낮(아침~오후)의 SEA-031 / SEA-032 | 밤바다 불빛 관찰(기존 세계 이벤트) + 지식 `navigation_marks` 접함 | 구현 |

- **저장**: `GameState.connections[연결ID] = {stage, first_day, last_day, trigger_observation_id, evidence[], history[]}`.
  `evidence`에는 실제 기록 ID(창문 문장 ID, 밤바다 불빛 Observation ID, 지식 출처 문장 ID)만 들어갑니다.
  `connections`가 없는 기존 v2 세이브는 빈 이력으로 로드되고 다른 기록은 그대로 유지됩니다 (버전 번호는 2 유지).
- **중복/발전**: 같은 연결 ID·단계는 한 번만 출력. 다음 단계는 앞 단계가 기록된 뒤에만 출력.
- **지식 단계**: 연결 조건은 `encountered < understood < applied` 순위로 비교합니다 (접함을 이해함으로 보지 않음).
- **영향 없음**: 가설·탐구·메모벽·지식 단계·문 해금은 바꾸지 않습니다.
- **`followUpIds`와의 관계**: `followUpIds`는 "다음에 나올 수 있는 관찰" 후보 관계일 뿐이라 연결 판정에 쓰지 않습니다.
  사고 연결은 `CONNECTIONS`에 트리거·선행 조건을 명시한 것만 발생합니다.
- **검증**: 정의가 존재하지 않는 관찰/지식/탐구 ID를 참조하면 모듈 로드 시 실패합니다 (T10).
- 응답의 `connection` 필드(`{id, stage}` 또는 `null`)로 내부적으로 구분할 수 있고, 화면에는 팝업 없이 문장만 보입니다.
