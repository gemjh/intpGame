- 원본 HTML은 그대로 두고 빌드할 때 편집기 CSS와 JS를 주입합니다(`build.py`). 원본의 이미지, 버튼, 스크립트는 바꾸지 않았습니다.

- 초기 배치는 원본 HTML의 인라인 위치값에서 자동으로 계산합니다.

## 4. 알려진 문제와 제한 사항

**교체 이미지 크기 규칙(최종)**: 가구 이미지를 바꿀 때는 화면에서 차지하는 **면적**을 원본과 같게 유지하고 가로·세로는 새 이미지 비율에 맞춥니다. 처음에는 높이만 유지했는데, 칠판과 책상이 너무 좁아져서 면적 기준으로 바꿨습니다. 기본 너비: 거울 11.26%, 창문 18.23%, 칠판 15.61%, 책상 22.50%. 이전 비율로 저장된 배치도 불러올 때 같은 규칙으로 자동 보정합니다. 아래 0~0-2 항목에 적힌 '높이 유지' 내용은 이 규칙으로 대체되었습니다.

0-5. **창문 이미지 2차 교체(2026-10-08)**: 새 창문 이미지도 체크무늬가 그려진 가짜 투명 배경이었습니다. 체크무늬를 제거하고(73%) 541×700으로 정리했습니다. 기본 너비는 18.23%입니다.

0-4. **칠판 이미지 2차 교체(2026-10-08)**: 더 가로로 긴 칠판 이미지(투명 배경)로 다시 바꿨습니다. 여백을 정리해 598×700이고, 기본 너비는 15.61%입니다.

0-3. **책상 이미지 교체(2026-10-08)**: 받은 이미지(1536×1024)는 체크무늬가 그려진 가짜 투명 배경이었습니다. 체크무늬를 제거하고(68%) 694×700으로 정리했습니다. 머그컵·노트 같은 흰 물체와 책상 다리 사이 공간이 올바르게 처리된 것을 확인했습니다.

0-2. **칠판 이미지 교체(2026-10-08)**: 받은 이미지(1536×1024)는 이미 투명 배경이었습니다. 여백만 잘라 478×700으로 축소했습니다. 높이를 기존과 같게 맞춘 결과 기존 칠판보다 좁게 보이므로 크기 조절이 필요할 수 있습니다.

0-1. **창문 이미지 교체(2026-10-08)**: 받은 이미지(1536×1024)는 투명 배경이 아니었습니다. 체크무늬가 그림에 그려져 있는 RGB 이미지였습니다. `tools/remove_checker_bg.py`로 이미지 가장자리와 이어진 밝은 무채색(체크무늬) 영역만 투명하게 바꾸고(약 61%), 여백을 잘라 626×700으로 축소했습니다. 그림 안쪽의 흰 커튼은 그대로 남았습니다. 화면상 높이는 기존 창문과 같게 두었고, 너비는 21% → 18.31%입니다.

0. **거울 이미지 교체(2026-10-08)**: 사용자가 준 이미지(1212×1297, 투명 배경)의 빈 여백을 잘라내고 404×800으로 축소해 `assets/mirror-new.png`로 저장했습니다. `build.py`의 `IMAGE_OVERRIDES`가 빌드할 때 원본 거울 이미지를 이 파일로 바꿉니다. 원본 HTML은 그대로입니다. 화면상 높이는 기존 거울과 같게 두고 너비만 새 비율(8% → 15.86%)로 맞췄습니다. 비율 유지 상태로 저장된 이전 배치를 불러오면 높이와 위치는 유지하고 너비만 새 비율로 자동 보정합니다.

1. **실제 갤럭시 기기에서는 아직 테스트하지 않았습니다.** 모바일 에뮬레이션과 터치 이벤트 시뮬레이션으로만 확인했습니다. 삼성 인터넷과 크롬에서 두 손가락 확대, 드래그, 파일 내보내기와 가져오기를 실제로 확인해야 합니다.
2. **방 배경의 검은 영역**은 위 1절에서 보고한 대로 원본 그대로 두었습니다.
3. **게임 모드 클릭 판정은 원본 그대로 사각형 기준입니다.** 앞에 있는 가구의 투명 부분이 뒤에 있는 가구 클릭을 가로챌 수 있습니다. 원본 동작을 보존하려고 바꾸지 않았고, 편집 모드에서만 알파 기준으로 판정합니다.
4. **편집 중에는 하단 기록/다음 시간 버튼을 숨깁니다.** 패널 공간을 확보하기 위해서이며, 완료를 누르면 다시 나타납니다. 시계는 계속 표시됩니다.
5. **원본의 같은 z-index**(침대·책장=3, 창문·거울=1)는 화면에 보이는 순서를 유지한 채 1~9로 다시 매겼습니다.
6. **저장하지 않은 변경**은 새로고침하면 사라집니다. 자동 저장은 없고, JSON을 가져온 뒤에도 저장을 눌러야 유지됩니다. 상태 줄에 저장하지 않은 변경이 있다고 표시됩니다.
7. 확대한 상태에서 목록으로 가구를 선택하면 해당 가구가 화면 밖에 있을 수 있습니다. 이때는 **맞춤** 버튼을 누르거나 + 버튼(선택 가구 중심으로 확대)을 쓰면 됩니다.
8. 편집 모드에서는 방 영역 밖으로 나간 가구 부분이 잘려 보입니다. 게임 모드에서는 원본처럼 보입니다.
9. 원본 viewport 설정(`user-scalable=no`)을 유지했기 때문에 브라우저 기본 확대는 되지 않고, 편집기 확대 기능을 사용합니다.
10. 원근감 문제는 자동으로 수정하지 않았습니다.
11. HTML 파일이 약 4.7MB(이미지 내장)라서 모바일 첫 로딩이 느릴 수 있습니다. 원본과 같은 수준입니다.

## 5. 데이터 구조 (이후 캐릭터 이동과 충돌 판정용)

- 좌표계: 방 이미지 1200×800 px, 원점은 왼쪽 위, `x,y`는 가구 중심점
- 가구별 항목: `id, name, x, y, width, height, scale, rotation(도, 시계 방향 +), aspectLocked, z, visible, bounds{left,top,right,bottom}`
- `bounds`는 회전을 반영한 외곽 사각형입니다. `rotation`이 없는 이전 JSON도 0°로 불러옵니다.
- 게임 코드에서는 `window.IntpLayout.get()`으로 현재 배치를 읽을 수 있습니다.
- 충돌 판정에는 `bounds`를 시작점으로 쓸 수 있습니다. 실제 바닥 점유 영역(footprint)은 이미지 사각형과 다르므로 다음 단계에서 별도 필드로 추가할 것을 권장합니다.
